chest (1) Full reference · v0.1.0

Standalone, offline-first, highly concurrent file organization and storage intelligence. Written in Go, packaged as a single static binary.

Installation #

1 · Go install #

If you have Go installed, compile directly into your Go bin directory:

go install github.com/Aswanidev-vs/chest/cmd/chest@latest

Ensure your Go bin path ($GOPATH/bin or %USERPROFILE%\go\bin) is on your system PATH.

2 · Curl one-liner (macOS & Linux) #

Downloads and runs install.sh:

curl -sSL https://raw.githubusercontent.com/Aswanidev-vs/chest/main/install.sh | bash

The script checks that Go is installed and recent enough, runs go install, verifies the install with chest version, and prints PATH advice if the install directory is not on your PATH. Use --to <dir> to install into a custom directory, --source to build from a local clone, or --uninstall to remove the binary.

3 · Windows PowerShell #

Downloads and runs install.ps1:

irm https://raw.githubusercontent.com/Aswanidev-vs/chest/main/install.ps1 | iex

The PowerShell installer does the same work as install.sh: checks Go, runs go install, runs chest version to verify, and reports whether the install directory is on PATH. Pass -To <dir>, -Source, or -Uninstall for the same options. Works on PowerShell 5.1 (default in Windows 10/11) and PowerShell 7+.

4 · Build from source #

git clone https://github.com/Aswanidev-vs/chest.git
cd chest
make build

Quick start #

Sort the files in your current folder with the default rules:

$ chest sort

Preview the moves without changing anything:

$ chest sort ~/Downloads --dry-run

Revert the most recent sort:

$ chest undo
Always preview first. A dry-run is the difference between “I want to run this” and “I know what this will do.” chest sort --dry-run is one flag; use it.

Architecture #

CHEST is built as four small systems, each replaceable:

scanner
parallel directory walk via fastwalk.
scorer
filename and content scoring borrowed from fzf/src/algo.
planner
collision-checked move graph; logs every operation to ~/.chest/history.db.
index
pure-Go SQLite (ncruces/go-sqlite3) for metadata, hashes, and stats.

Plugins sit outside the planner over a HashiCorp go-plugin RPC boundary — they can crash without affecting the planner.

Core CLI commands #

chest sort #

Organize files based on rules or presets.

-t, --type
Group by file category (Images, Videos, Documents, …).
-s, --size
Group by size thresholds.
-f, --format
Group by file extension.
-p, --preset
Built-in preset: downloads, media, developer, documents, photos.
--rule
On-the-fly custom rule: "expression -> destination".
-i, --into
Custom root destination directory.
-n, --dry-run
Simulate without moving files.
-y, --yes
Skip interactive confirmation.

chest search #

Blazing-fast search using fastwalk parallel traversal and fzf/src/algo scoring.

-c, --content
Grep inside file contents. Shows line number and match snippet.
-t, --type
Filter by category: image, code, …
-e, --ext
Comma-separated extension filter: go,md,png.
-s, --size
Size condition: >1GB, <50MB.
-m, --modified
Time condition: >30d.
-r, --regex
Regex pattern matching.
-j, --json
Emit results as JSON for shell scripting.

chest watch #

Continuous watcher powered by fsnotify. When files finish downloading, CHEST immediately sorts them.

$ chest watch ~/Downloads --preset media --debounce 500ms

chest undo & history #

Every run is recorded with an integer ID. chest undo reverts the latest run; chest undo <id> reverts a specific one. chest history lists what’s there.

$ chest history
$ chest undo      # latest
$ chest undo 3    # by id

chest index & clean #

CHEST persists file metadata and optional SHA-256 hashes into local SQLite at ~/.chest/index.db.

chest index [path] --hash
Compute incremental SHA-256 hashes.
chest index --clear
Empty the indexed-files table without deleting undo history.
chest clean
Empties the index cache.
chest clean --all
Deletes the entire SQLite database file.

File intelligence: stats, duplicates, analyze #

chest stats
Storage and category distribution breakdown.
chest duplicates [path]
Byte-for-byte duplicate finder using SHA-256.
chest analyze [path]
Health report: stale files (>180 days), zero-byte files, largest consumers.

man · preset · version #

Three small verbs that don’t need their own pages:

chest man <command>
Like the Linux man command, but built in. Full description, flags, and examples for any verb.
chest preset
List every built-in sorting preset and the file types it targets.
chest version
Print version, OS/architecture, and the Git commit SHA when built from a checkout.
$ chest man sort
$ chest preset
$ chest version

Plugin architecture & guide #

Why external plugins? CHEST uses hashicorp/go-plugin over RPC. Plugins run in separate processes. If a plugin crashes or hangs, CHEST’s planning and filesystem-safety mechanisms stay 100% protected.

How plugins work #

A CHEST plugin is an executable binary paired with a manifest.json, placed in ~/.chest/plugins/<plugin-name>/. Plugins can expose:

  • custom classifiers (e.g. “is this an anime episode?”),
  • custom rules (additional predicates for the rule engine),
  • new file presets (named rule bundles for -p).

Building a plugin: step by step #

Step 1 · create the project

$ mkdir chest-anime-plugin
$ cd chest-anime-plugin
$ go mod init chest-anime-plugin

Step 2 · write the binary (main.go)

package main

import (
    "strings"
    hplugin "github.com/hashicorp/go-plugin"
    "github.com/Aswanidev-vs/chest/internal/plugin"
    "github.com/Aswanidev-vs/chest/internal/models"
)

type AnimePlugin struct{}

func (a *AnimePlugin) GetInfo() (plugin.Manifest, error) {
    return plugin.Manifest{
        Name:         "anime",
        Version:      "1.0.0",
        Description:  "Classifies anime and manga media",
        Capabilities: []string{"classifier"},
        Binary:       "anime-plugin",
    }, nil
}

func (a *AnimePlugin) Classify(filename string, ext string) (string, error) {
    lower := strings.ToLower(filename)
    if strings.Contains(lower, "[subs]") || strings.Contains(lower, "1080p") {
        return "Anime", nil
    }
    if ext == "cbr" || ext == "cbz" {
        return "Manga", nil
    }
    return "Other", nil
}

func (a *AnimePlugin) GetCustomRules() ([]models.Rule, error) {
    return nil, nil
}

func main() {
    hplugin.Serve(&hplugin.ServeConfig{
        HandshakeConfig: plugin.HandshakeConfig,
        Plugins: map[string]hplugin.Plugin{
            "classifier": &plugin.ClassifierPluginRPC{Impl: &AnimePlugin{}},
        },
    })
}

Step 3 · write manifest.json

{
  "name": "anime",
  "version": "1.0.0",
  "description": "Classifies anime and manga media",
  "author": "YourName",
  "capabilities": ["classifier"],
  "binary": "anime-plugin"
}

Step 4 · build and install

$ go build -o anime-plugin .
# install into CHEST
$ chest plugin install .

Step 5 · verify

$ chest plugin list
$ chest plugin info anime

manifest.json — chest-plugin(5) #

The manifest declares the plugin’s identity and what it can do. All fields are required unless marked optional.

name
Lowercase, hyphen-separated identifier. Becomes the directory name under ~/.chest/plugins/.
version
Semantic version string. Used to detect upgrades.
description
One-line description. Shown by chest plugin info.
author
Plugin author’s name or handle.
capabilities
Array of: classifier, rules, presets. At least one.
binary
Executable name relative to the plugin directory.

Managing plugins via the CLI #

chest plugin list
Show all installed plugins.
chest plugin info <name>
View capabilities and author info.
chest plugin install <dir>
Install a local plugin folder.
chest plugin remove <name>
Uninstall completely.
